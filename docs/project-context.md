## 用户明确提出的需求

- 介绍个人背景、经历和项目，避免做成简历翻版。
- 支持中英文切换。
- 使用 React / Next.js，架构应允许后续独立项目接入。
- 支持访客操作三维模型，而不仅展示截图。
- 将自己开发的 Project Search 纳入作品展示。
- 从求职角度保持清晰专业定位。
- 依据 e-modern-product.html 设计稿制作 preliminary 版本。

## 个人背景和表达主线

- 本科、硕士、博士均为土木工程背景。
- 专业能力：力学计算、有限元模拟、MATLAB 动力学方程与仿真。
- 自学代码约两年，主要涉及前后端开发，Project Search 是已有成果。
- AI 仍处于探索阶段，已有 API 调用经验，尚无成熟成果。
- 讨论形成的定位：计算型土木工程人才，以力学和仿真为专业核心，以工程软件开发为差异化能力，AI 作为当前探索方向。
- 建议英文表述：Computational civil engineer working across mechanics, simulation, and software.

## 内容架构

- Home：首页定位、精选项目、能力方向、当前探索、个人故事和联系入口。
- Work：项目列表与独立案例详情。
- About：个人故事、成长路径、工作方式。
- Resume：教育、工作、研究成果、技能及 PDF 下载。
- Lab / Explorations：小型实验与 AI 探索，可先作为项目分类。
- 联系方式放在导航、页脚和行动区，第一版无需单独联系页。

项目方向包括 Computational Engineering、Engineering Software、Modeling & Visualization、Lab / Explorations。有限元案例讲清假设、边界条件、求解和验证；MATLAB 案例展示动力方程与响应；软件案例解释需求、架构、技术决策和成果。

## 讨论中的目标技术架构（不代表已经实现）

- React + Next.js App Router + TypeScript。
- 主站负责个人内容和项目索引；独立应用保持各自部署与业务数据边界。
- 双语目标路径为 /zh 和 /en，切换时保留当前页面，并预留双语 SEO。
- 内容先采用 MDX 或结构化文件；项目注册数据统一管理标题、分类、封面、技术、精选状态和 Demo 入口。
- 页面默认以服务端内容为主，3D、地图等浏览器交互按需加载。
- 项目接入分为案例页、原生交互组件、独立应用入口；Multi-Zones 仅作后续选项。
- 保留 Monorepo 扩展空间，尚不要求立刻拆分全部共享包。
- 暂缓复杂 CMS、统一登录和共享业务数据库。

## 3D 与 Project Search

- 三维模型发布格式考虑 GLB/glTF；基础查看器与 Three.js / React Three Fiber 高级交互可分别接入。
- 模型按需加载，提供封面、加载反馈和图片/视频降级；大型资产可放对象存储/CDN。
- Project Search 在历史讨论中被描述为搜索、地图、结果表格与 AI 助手组成的业务应用。
- 主站展示案例故事；公共交互演示使用脱敏或虚构数据，保持独立部署。
